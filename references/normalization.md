# 统一剧本：改什么、绝不改什么

这套规则来自实际整理 2 人话剧《Brave to Speak》时定下的约定，同一系列剧本沿用。

## 分界线

| 属于「说明/格式」，**要**统一 | 属于「台词」，**绝不**改 |
|---|---|
| 章节编号写法（`①` / `第 1 步` / `1)` 混排） | 台词正文的每一个字、每一个标点 |
| 角色标签的实现（`A:` / `A：` / `A ：`） | 台词里的错误拼写（`dosen't`、`l am`） |
| 舞台指示的标记形式（`（……）` / `★` / 斜体） | 台词里的口语断续、重复、多余空格 |
| 层级缩进、空行、对齐 | 齐诵行里 `&` 的写法 |
| 大小标题的样式 | 台词语气词（`Ah!` / `Oh...`） |

**原则**：把「读者用来理解结构的脚手架」统一，把「演员要照着念的每一个字」冻住。

统一前先把原稿的标记体系抄一份底：`（……）` 是什么、`★` 是什么、哪些是斜体。统一后这些语义必须一一对应，不能丢。

## 四类标记（统一后）

```
【场景】舞台环境、灯光、时间地点变化
【动作】走位、肢体表演、面向谁、道具动作
【提示】语气、节奏、停顿、音量、情绪、包袱点
A：   单人台词（全角冒号，标签与台词之间一个空格都不要多加）
A & B：齐诵台词
```

`【场景】/【动作】/【提示】` 在成品里加粗。台词标签保持不加粗，让眼睛能一眼分出「这是谁说」和「这是怎么演」。

### 归类的判断题

| 原句 | 归到哪 | 理由 |
|---|---|---|
| `（B 拿着地图，微笑走上台。）` | 动作 | 有具体肢体 |
| `（校园国际文化节。A 站在迎新台前……）` | 场景 | 交代环境、不涉及走位 |
| `★ 说完停 1 秒，等观众笑。` | 提示 | 节奏，不是动作 |
| `说到 freezes 时定住两秒` | 动作 | 身体停住 |

边界不清时按「观众看得见吗」判：**看得见的身体位移 → 动作；听得出的节奏/语气 → 提示；需要脑补的环境 → 场景。**

## 三个必查的坑

1. **引用了不存在的词。** 原稿写「说到 freezes 时定住」，但全剧没有 `freezes`。这是动作行里的引用错误 → 属于可统一范围，改成实际存在的词（`how to respond`）。
2. **半角冒号和不定长空格。** `A:` `A ：` `A  :` 混用会很脏，统一成全角 `A：`，台词本体不动。
3. **编号体系打架。** 一份文档里同时出现 `① ② ③`、`一、二、三`、`第 1 步`、`1. 2. 3.` 时，定一套：一级用 `一、二、三、四`，子项用 `1. 2. 3.`，去掉圈码和小括号。

## 交稿时必须附上「疑点清单」

台词不改 ≠ 装看不见。整理完要在回复里列出**没有改但建议确认**的地方，例如：

- `第 2 场` 的 `l am chip` —— 开头是半角小写字母 `l`，大概率应为大写 `I`
- `I'm fine, thank you, and you?  e  I always…` —— 中间多了一个孤立的 `e`
- `dosen't` —— 应为 `doesn't`
- 台词里三处以上的连续空格 —— 确认是有意的停顿还是排版噪音

这几条正好由 `scripts/validate_data.py` 的 lint 规则自动扫出来（见「自动检查」一节），不要靠肉眼。

## 自动检查

```bash
python scripts/validate_data.py data.json            # 结构 + 疑点清单
python scripts/check_fidelity.py --source 原稿.docx --data data.json   # 台词一字未改
```

`check_fidelity.py` 是**发布闸门**：只要有一句台词在源文件里找不到逐字对应，就返回非零退出码，不许交付。这一步把「我保证没改台词」变成可执行的证明。

它只做空白归一和引号/破折号的全半角折合，不做同义词或拼写容错——所以它能抓出「模型顺手把台词改通顺了」这类事故。
