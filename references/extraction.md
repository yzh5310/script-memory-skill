# 抽取：把任意格式的剧本读成文本

## 一条命令

```bash
python scripts/extract_script.py "<剧本文件>" -o <工作目录>
```

产出两个文件（放在输入文件同级目录，或 `-o` 指定）：

| 文件 | 用途 |
|---|---|
| `<名字>.txt` | 纯文本，一段一行。**优先读这个** |
| `<名字>.blocks.json` | 保真结构：每段的样式名、是否整段加粗/斜体、混排时的 run 明细 |

`blocks.json` 里 `"runs"` 存在，说明这一段是**混排**（比如整段正常但某几个词加粗、或台词里嵌了 `★` 提示）——这正是「动作/提示」最常出现的位置，需要重点看。

## 支持的格式

| 格式 | 依赖 | 备注 |
|---|---|---|
| `.docx` | 无（标准库解包 XML） | 首选。段落样式、加粗、斜体都能读到 |
| `.pptx` | 无 | 逐页抽取，页间插 `── slideN ──` 分隔 |
| `.xlsx` / `.csv` / `.tsv` | 无 | 每行渲染成 `单元格 \| 单元格` |
| `.txt` / `.md` | 无 | 原样读，自动试 utf-8 / gbk / big5 |
| `.html` / `.htm` | 无 | 去标签，块级标签转换行 |
| `.json` | 无 | 递归收集所有字符串字段 |
| `.srt` / `.vtt` | 无 | 去时间轴、去序号，合并成段 |
| `.rtf` | 无 | 粗暴剥离控制字 |
| `.pdf` | `pypdf` 或 `PyPDF2`，或系统 `pdftotext` | 三者都没有时会明确报错并给替代方案 |

缺失 PDF 依赖时，不要在这上面耗时间：让用户先另存为 `.docx` 或 `.txt`，或者临时装一下。

如果确实需要装，**装进隔离环境，别装到全局**（全局安装会污染本机其他项目）：

```bash
# 推荐：项目内虚拟环境
python -m venv .venv
.venv/bin/pip install pypdf          # Windows: .venv\Scripts\pip install pypdf

# 退一步：至少不要加 sudo，也不要动系统 Python
python -m pip install --user pypdf
```

包本身来自 PyPI 官方源即可；不要换成来路不明的镜像源。

`.doc` / `.odt` / `.pages` / `.wps` 是专有格式，直接告诉用户另存为 `.docx`，不要尝试解析。

## 读不到内容时的排查顺序

1. 文件是不是扫描件 / 图片？PDF 抽出来是空的 → 需要 OCR，超出本 skill 范围，告诉用户。
2. 是不是共享链接而不是本地文件？先下载到本地。
3. 是不是 Word 里的文本框、批注、修订？标准库只读正文，文本框内容可能漏。让用户把内容复制到新文档里再试。
4. 抽出来的段落数远少于预期 → 打开 `blocks.json` 看看是不是全落在一个段落里（有些模板把整页塞进一个文本框）。

## 抽完之后先做三件事

1. **数一遍句子总数和角色数**——这个数字后面每次校验都要对齐。
2. **找标记体系**——原文用什么区分「台词 / 动作 / 提示 / 场景」？常见有：`（……）` 圆括号、`★……`、`【……】`、斜体、`[Stage direction]`、单独的「动作：」行。记下来，后面统一时要保持语义一致。
3. **找角色标签**——`A:`、`甲：`、`CHARLES:`、`—李雷`……以及齐诵是怎么写的（`A & B:`、`合：`、`所有人：`）。标签本身的写法**属于可以统一的说明部分**，可以规范化成 `A：`；但标签后面那句话是台词，一个字都不能动。
